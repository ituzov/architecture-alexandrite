# Планирование: анализ, проблемы и решения

## 1. Что болит прямо сейчас

| # | Боль                                        | Почему это реально больно                 |
|---|---------------------------------------------|-------------------------------------------|
| 1 | **Одиночные инстансы сервисов**             | Один EC2 падает — весь сервис тоже.       |
| 2 | **Одиночная Postgres + RabbitMQ**           | Нет резерва → стоп‑продажи при сбое.      |
| 3 | **Одна и та же Postgres и читает, и пишет** | Нагрузка растёт — начинаем тормозить.     |
| 4 | **Релизы руками**                           | Человеческий фактор + медленно.           |
| 5 | **E2E‑тесты вручную одним QA**              | Задержки релизов уже > месяца.            |
| 6 | **Нет нормального мониторинга**             | Чтобы понять, «почему 500?», тратим часы. |
| 7 | **Зоопарк стеков (Java+C#+Vue+React)**      | Узких спецов мало— задачи висят.          |
| 8 | **Инфра не в коде (No IaC)**                | Новый стенд поднимаем неделями.           |
| 9 | **Не хватает DevOps/QA‑авто**               | Долги копятся, команда выгорает.          |

---

## 2. Что делаем (инициативы)

| Приоритет | Инициатива                                   | Что конкретно                                                                 |
|-----------|----------------------------------------------|-------------------------------------------------------------------------------|
| **1**     | **Контейнеризация + Kubernetes**             | Docker → Yandex Managed K8s, минимум 2 реплики на сервис.                     |
| **1**     | **HA‑Postgres + read‑реплика**               | Master для записи, реплика для чтения; автоматический фейловер.               |
| **1**     | **RabbitMQ‑кластер с quorum‑очередями**      | События не теряем даже при падении узла.                                      |
| **1**     | **CI/CD2.0**                                 | GitHub Actions: unit+E2E, auto‑deploy в dev; ArgoCD — release/prod по кнопке. |
| **2**     | **Мониторинг и логи**                        | Prometheus + Grafana + Loki, алерты в Пачку.                                  |
| **2**     | **Сага/идемпотентность статусов**            | Заказ хранится как «источник истины», ретраи безопасны.                       |
| **3**     | **IaC (Terraform)**                          | EC2, VPC, базы, RabbitMQ — всё через код с ревью.                             |
| **3**     | **Обучение/найм QA‑автоматизатора и DevOps** | Закрываем узкие места по тестам и инфре.                                      |

---

## 3. Как это выглядит через 6 месяцев

* Сервисы крутятся в K8s, автоскейлятся, падение узла незаметно клиентам.
* Postgres: master + read‑replica, бэкапы и фейловер занимают минуты, а не часы.
* RabbitMQ: минимум 3 ноды, есть DLQ, события не теряются.
* Релиз каждую неделю: dev — автоматически, prod — канареечка и кнопка «го».
* Grafana‑дашборды на мониторах, алерты в чате, MTTR < 30 мин.
* Весь клауд описан в Terraform, новый стенд = одна команда make apply.
* Появился QA‑авто и DevOps: тесты гоняются ночью, разработчики спят спокойно.

---

## 4. Если можно сделать **только три вещи**

1. **CI/CD 2.0** — убираем главный тормоз релизов, ловим баги раньше.
2. **Контейнеризация + Kubernetes** — фундамент для отказоустойчивости и быстрого скейла.
3. **HA‑база данных (master + read‑replica) + RabbitMQ‑кластер** — без живых данных бизнес не работает.

> 🔥 Эти три шага дают максимальный выхлоп: меньше простоев, быстрее фичи, спокойнее нервы.
